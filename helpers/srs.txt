# **HART Admin Agent — Software Requirements Specification (SRS)**

# **HART Admin Agent**

Learning-focused project

**Project type:** Multi-tenant AI hotel operations agent

**Primary technology:** Python, Flask, Gemini, LangGraph, SQL database

**Application:** Web-based hotel admin dashboard with an AI assistant.

**Development approach:** Incremental, step-by-step learning.

## **1. Project overview**

HART Admin Agent is an AI assistant integrated into the hotel SaaS platform.

Each registered hotel has its own data in the database, including:

- Hotel information
- Check-in and check-out timings
- Hotel policies
- Rooms and room types
- Bookings and reservations
- Guest information
- Revenue and operational information

Hotel owners and administrators can communicate with the AI agent through a dashboard.

The agent understands their questions and retrieves the correct information from the database.

**Example:**

Hotel A has a check-in time of 12 PM.

Hotel B has a check-in time of 2 PM.

Both administrators ask:

"What is our check-in time?"

The same AI agent answers differently because it retrieves information for the authenticated administrator's hotel.

## **2. Main objectives**

1. Build a single AI agent that supports multiple hotels.
2. Connect the agent to real hotel database information.
3. Allow administrators to ask questions in natural language.
4. Allow the agent to analyze hotel bookings and business data.
5. Introduce agent tools and multi-step reasoning.
6. Eventually allow the agent to perform approved hotel operations.
7. Learn how production-oriented AI agents are designed and developed.

## **3. Users and roles**

| User         | Responsibilities                                         |
| ------------ | -------------------------------------------------------- |
| Hotel Owner  | View hotel information, analytics and operations         |
| Hotel Admin  | Ask questions and manage authorized hotel operations     |
| System Admin | Manage platform-level agent configuration and monitoring |

The system must ensure that a hotel administrator cannot access another hotel's information.

## **4. Functional requirements**

### **FR-01: Landing page**

- Application landing page at `/`.
- Display project information.
- Provide login access.

### **FR-02: Admin authentication**

- Secure login.
- Identify the authenticated user.
- Retrieve their associated `hotel_id`.
- Restrict access based on role and permissions.

### **FR-03: Admin dashboard**

- Hotel overview.
- AI assistant chat interface.
- Recent conversations.
- Hotel statistics.
- Agent activity information.

### **FR-04: AI chat**

Administrators should be able to ask questions such as:

- What are our check-in and check-out times?
- What is our cancellation policy?
- How many rooms are available?
- How many bookings do we have this month?
- What is our occupancy rate?
- Which bookings are cancelled?

### **FR-05: Database-connected AI agent**

- Retrieve hotel-specific information dynamically.
- Use database tools to fetch relevant records.
- Avoid sending unnecessary database information to Gemini.
- Never invent hotel information when records are missing.
- Ensure every query is restricted to the authenticated hotel.

### **FR-06: Hotel analytics**

The agent should eventually answer questions about:

- Booking trends.
- Occupancy.
- Revenue.
- Cancellations.
- Room performance.
- Guest feedback.

### **FR-07: Hotel operations**

Future versions can support:

- Creating bookings.
- Modifying bookings.
- Cancelling bookings.
- Updating room availability.
- Updating prices.

Sensitive actions must require authorization and confirmation.

### **FR-08: Conversation management**

- Maintain conversation history.
- Keep conversations separate by user and hotel.
- Support follow-up questions.
- Avoid sharing memory across hotels.

## **5. Non-functional requirements**

| Requirement      | Description                              |
| ---------------- | ---------------------------------------- |
| Security         | Authentication and authorization         |
| Tenant isolation | No cross-hotel data access               |
| Accuracy         | Answers grounded in database information |
| Scalability      | One agent serving multiple hotels        |
| Maintainability  | Separate UI, agent, tools and services   |
| Reliability      | Handle database and LLM errors           |
| Observability    | Log agent activity and tool execution    |
